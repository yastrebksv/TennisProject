## 1. システム全体像

### 提供機能一覧

| 機能 | 説明 | 関連ファイル |
|------|------|-------------|
| ボール追跡 | 3フレーム連続入力からボール位置を検出 | `ball_detector.py`, `tracknet.py` |
| コート検出 | 14個のキーポイントでコート形状を特定 | `court_detection_net.py`, `court_reference.py` |
| 透視変換(ホモグラフィ) | カメラ映像→俯瞰座標への変換 | `homography.py` |
| 選手検出 | バウンディングボックスで選手位置を特定 | `person_detector.py` |
| バウンス検出 | ボール軌跡からバウンスフレームを予測 | `bounce_detector.py` |
| キーポイント補正 | コートの線分検出で検出点を補正 | `postprocess.py` |
| シーン分割 | 動画をラリー単位のシーンに分割 | `utils.py` |
| ミニマップ描画 | 俯瞰図にボール・選手の位置を可視化 | `main.py` |

## 3. 各パイプライン詳細

### [B] ボール検出パイプライン

| ステージ | 処理内容 | 入力 | 出力 | 改善可能な精度 |
|----------|---------|------|------|--------------|
| **B1** TrackNet推論 | 3フレーム連結(9ch)→ヒートマップ(256ch) | フレーム t-2, t-1, t (640×360) | 256chヒートマップ | **検出精度**: ボールが映っている場所を正しくヒートマップに反映できるか |
| **B2** ヒートマップ→座標 | 閾値(127)で二値化 | ヒートマップ | 二値画像 | **閾値チューニング**: ノイズと見逃しのトレードオフ |
| **B3** Hough円検出 | 円検出でボール候補を特定 | 二値画像 | (x, y) 座標候補 | **形状判定精度**: 円状のものをボールと認識する精度 |
| **B4** 距離フィルタ | 前フレームから80px以内か判定 | 現フレーム座標 + 前フレーム座標 | 確定 (x, y) | **時系列一貫性**: 物理的にありえない移動を除外する精度 |

### [C] コート検出パイプライン

| ステージ | 処理内容 | 入力 | 出力 | 改善可能な精度 |
|----------|---------|------|------|--------------|
| **C1** キーポイント検出 | 15chヒートマップ出力 | フレーム (640×360) | 15枚のヒートマップ | **キーポイント検出精度**: 14点をどれだけ正確にヒートマップに出せるか |
| **C2** ヒートマップ→座標 | 閾値(170)で二値化 | ヒートマップ | 二値画像 | **閾値チューニング** |
| **C3** Hough円検出 | 各キーポイントの中心座標を検出 | 二値画像 | 14個の (x, y) 候補 | **検出パラメータ精度** (minRadius=10, maxRadius=25) |
| **C4** 線分補正 | 80×80切り出し→Hough直線検出→交点計算 | C3の座標付近画像 | 補正済み (x, y) | **幾何補正精度**: コートの線分交点で位置を精密化 |
| **C5** ホモグラフィ算出 | 12構成から最小誤差の4点組を選出 | 14キーポイント + リファレンス座標 | 3×3変換行列 | **座標変換精度**: カメラ映像→俯瞰座標の変換誤差 |

### [D] 選手検出パイプライン

| ステージ | 処理内容 | 入力 | 出力 | 改善可能な精度 |
|----------|---------|------|------|--------------|
| **D1** Faster R-CNN推論 | 物体検出でPERSON(label=1)を抽出 | フレーム画像 | バウンディングボックス + スコア | **人物検出精度**: 選手を正しく検出できるか |
| **D2** 信頼度フィルタ | score > 0.85 のみ採用 | ボックス + スコア | フィルタ済みボックス | **閾値チューニング**: 観客除去と選手見逃しのバランス |
| **D3** コートマスクフィルタ | ホモグラフィでコート領域を特定 | ボックス + ホモグラフィ行列 | コート内の選手のみ | **領域フィルタ精度**: コート外のノイズ除去 |
| **D4** コート半面分類 | 選手をトップ/ボトムに分離 | フィルタ済みボックス + コートマスク | 上半面/下半面の選手リスト | **半面分類精度**: どちらのコートの選手かを正しく判定 |

### [E] バウンス検出パイプライン

| ステージ | 処理内容 | 入力 | 出力 | 改善可能な精度 |
|----------|---------|------|------|--------------|
| **E1** 軌跡補間 | 欠損フレームをcubic splineで補間 | ボール座標列(Noneあり) | 補間済み座標列 | **補間精度**: 欠損区間を物理的に妥当に埋められるか |
| **E2** 特徴量エンジニアリング | ラグ、差分、比率の12特徴量を算出 | 補間済み座標列 | 特徴量DataFrame | **特徴量設計**: バウンスを識別するための情報量 |
| **E3** CatBoost推論 | 勾配ブースティングで回帰予測 | 12特徴量 | 連続値(バウンス確率) | **モデル精度**: バウンスフレームを正しく予測 |
| **E4** 後処理 | 閾値(0.45) + 連続検出除去 | 予測確率列 | バウンスフレーム番号リスト | **後処理精度**: 重複除去と見逃しのバランス |

## 4. 精度改善マップ

各ステージで「何を改善すると、何が良くなるか」を整理する。

### 独立して改善できる精度の一覧

```
🔵 = DNNモデルの改善（学習データ・アーキテクチャ）
🟢 = 後処理アルゴリズムの改善（パラメータ・ロジック）
🟡 = 特徴量設計の改善
🔴 = 全体設計の改善
```

| ID | 改善対象 | 種別 | 独立性 | 影響範囲 |
|----|---------|------|-------|---------|
| B1-acc | TrackNetのボール検出精度 | 🔵 | **完全独立** — 学習データ追加・アーキテクチャ変更で改善 | ボール追跡全体 |
| B3-acc | Hough円検出のパラメータ最適化 | 🟢 | **完全独立** — B1の出力に対する後処理 | ボール座標精度 |
| B4-acc | 距離フィルタの閾値最適化 | 🟢 | **完全独立** — 物理制約パラメータの調整 | 誤検出除去率 |
| C1-acc | コートキーポイント検出DNNの精度 | 🔵 | **完全独立** — 学習データ追加で改善 | コート検出全体 |
| C4-acc | 線分検出によるキーポイント補正精度 | 🟢 | **完全独立** — Hough直線パラメータの調整 | キーポイント位置精度 |
| C5-acc | ホモグラフィ算出の構成選択精度 | 🟢 | **完全独立** — 候補構成の追加・評価関数の改善 | 座標変換全体 |
| D1-acc | 人物検出モデルの精度 | 🔵 | **完全独立** — モデル変更・ファインチューニング | 選手検出全体 |
| D2-acc | 信頼度フィルタの閾値最適化 | 🟢 | **完全独立** — 0.85の見直し | 選手の検出漏れ/誤検出 |
| D4-acc | コート半面分類ロジック | 🟢 | C5に依存 — ホモグラフィ精度に左右される | 選手の位置分類 |
| E1-acc | 軌跡補間の精度 | 🟢 | B全体に依存 — ボール検出結果を入力とする | バウンス検出の入力品質 |
| E2-acc | 特徴量設計 | 🟡 | **完全独立** — 新しい特徴量の追加検討 | バウンス予測精度 |
| E3-acc | CatBoostモデルの精度 | 🔵 | E2に依存 — 特徴量が変われば再学習が必要 | バウンス検出精度 |
| E4-acc | 後処理(閾値・連続除去)の最適化 | 🟢 | **完全独立** — 0.45の見直し | バウンス最終出力品質 |

### 依存関係グラフ

```
B1-acc ──→ B3-acc ──→ B4-acc ──→ E1-acc ──→ E2-acc ──→ E3-acc ──→ E4-acc
(独立)     (独立)     (独立)     (B依存)    (独立)     (E2依存)   (独立)

C1-acc ──→ C4-acc ──→ C5-acc ──→ D4-acc
(独立)     (独立)     (独立)     (C5依存)

D1-acc ──→ D2-acc
(独立)     (独立)
```

**重要**: 「独立」は**そのステージ単体の改善作業**が他のステージの改善作業に影響しないという意味。入出力のデータ依存はあるが、改善活動自体は並行して進められる。

### チーム間インターフェース（契約）

各チームが疎結合で動けるよう、チーム間の入出力を明確に定義する。

| 提供元 → 提供先 | データ形式 | 契約 |
|-----------------|-----------|------|
| **ボール検出** → バウンス検出 | `List[Optional[Tuple[int,int]]]` | フレームごとのボール座標。検出失敗時は `None` |
| **コート検出** → ホモグラフィ | `List[Tuple[int,int]]` (14点) | 14個のキーポイント座標。検出失敗時は `None` |
| **ホモグラフィ** → 選手分類 | `np.ndarray (3×3)` | 透視変換行列。算出失敗時は `None` |
| **ホモグラフィ** → 可視化 | `np.ndarray (3×3)` 逆行列 | ミニマップ投影用。算出失敗時はミニマップ非表示 |
| **選手検出** → 可視化 | `List[Tuple[bbox, center]]` | トップ/ボトム別の選手リスト |
| **バウンス検出** → 可視化 | `List[int]` | バウンスが発生したフレーム番号 |

### チーム別KPI（精度指標）

| チーム | KPI | 測定方法 |
|--------|-----|---------|
| ボール検出器(B1) | ボール検出率 (Recall) + 誤検出率 (FPR) | アノテーション付きテスト動画で評価 |
| ボール後処理(B2-B4) | フィルタ後の精度 (Precision) | B1の出力に対するフィルタの効果測定 |
| コート検出器(C1) | キーポイント検出率 + 位置誤差(px) | 正解座標との距離で評価 |
| 線分補正(C4) | 補正前後の位置誤差改善量 | C3出力とC4出力を正解と比較 |
| ホモグラフィ(C5) | 再投影誤差(px) | 14点の変換後誤差で評価 |
| 人物検出(D1) | mAP@0.5 | COCO形式の評価 |
| 半面分類(D3-D4) | 分類正解率 | 上下コートの分類Accuracy |
| 軌跡補間(E1) | 補間位置の誤差(px) | 意図的にNoneにした区間で評価 |
| バウンス予測(E3) | Precision / Recall / F1 | アノテーション付きバウンスフレームで評価 |

## 補足: 疎結合を維持するための設計原則

1. **インターフェースで分離**: 各パイプラインは入出力の型を守れば、内部実装を自由に変更できる
2. **Noneの伝播ルール**: 検出失敗時は `None` を返し、下流は `None` を受け取ったらスキップまたはフォールバック
3. **評価の独立性**: 各小チームは自チームのKPIを独立して計測・改善できる
4. **モデルの差し替え可能性**: DNN部分(B1, C1, D1, E3)はインターフェースさえ守れば別モデルに差し替え可能
